# 실제 가격 데이터 확보·진단 결과 (2026-11-12, 한국 시간)

이번 작업은 기존 가격 계산을 유지하고 실제 CSV를 채우는 데 집중했다. 사진 분석·집기 편집·앱 배포 구조는 변경하지 않았다.

## 실제 반영 결과

- **실제 매물 7건: 제빙기 4건, 커피머신 3건.** 출처는 소상공간의 공개 개별 상품 상세 페이지다.
- 자동 반복 크롤링으로 확보한 매물 0건, 온비드 수집 0건, **공개 원문을 개별 검토하고 수동 CSV 경로로 반영한 매물 7건**이다. 자동 수집 권한이 확인됐다는 뜻이 아니다.
- 각 페이지의 HTTP 200, 공개 Product JSON-LD의 KRW 가격·UsedCondition·InStock, 제목과 설명을 직접 대조했다. 검색 결과의 가격을 그대로 복사하지 않았다. 상세 404·전화문의·신품·품절 상태 불명확 후보는 이번 반영에서 제외했다.
- 원본 URL·검증일·검증자·검증 메모는 [manual_reviews.csv](../data/manual_reviews.csv), 가격 조회용 데이터는 [listings.csv](../data/listings.csv)에 있다. 사진·판매자 연락처·본문 전체를 재배포하지 않는다.
- 판매 중 게시가 기준이며 실제 거래 완료액·공매 낙찰가가 아니다. 배송·설치·보증·세금 포함 조건에 따라 실제 지출/매각액은 달라진다. 수집 시점의 스냅샷으로 이후 판매 완료·가격 변경을 보장하지 않는다.

## 기존에 0건이었던 이유와 출처 조사

1. `data/sources.json`이 비어 있어 자동 수집기가 등록 출처를 실행할 수 없었다. 크롤러 코드만 존재한다고 데이터가 자동 생성되는 구조는 아니며 업로드 시 수집하지 않는다.
2. 이 작업 환경에는 `DATA_GO_KR_KEY`가 없어 온비드 인증 수집을 시작할 수 없었다. **API 조회 미실행과 API가 정상 응답한 결과 0건은 다르다.** Streamlit 운영 Secrets의 키 설정 여부는 이 환경에서 확인할 수 없다.
3. 기존 `import-csv`도 자동 수집 허용 등록을 요구해 수동 검증 자료를 넣기 어려웠다. `import-manual`을 분리했다.
4. 기존 정제는 잘못된 행을 이유 없이 버렸다. 특히 정상 장비명에 포함된 “원두 커피 그라인더”까지 무관 물품으로 제외하는 조건을 확인해 보완했다. 품목 키워드·부품·묶음 검사는 유지한다.

## 수동 CSV 입력과 기존 DB 연결

[data/manual_template.csv](../data/manual_template.csv)의 헤더를 복사한 새 파일에 원문을 확인한 사실을 입력한다. 기존 16개 열 외에 다음이 필수다.

- `verified_at`: 실제 확인일(YYYY-MM-DD), 최근 30일 이내. `collected_at`와 같아야 한다.
- `reviewed_by`: 검증자 표시.
- `verification_note`: 가격·중고 여부·판매 상태·모델·묶음 여부 등을 확인한 메모.
- `is_sample=false` 명시. 미확인 가격/모델은 만들어 넣지 않는다.

```bash
python crawler.py import-manual /path/verified.csv
# 자동 수집 허용 출처용 기존 import-csv 명령도 유지
```

수동 입력 명령 자체는 외부 웹사이트에 요청하지 않는다. 별도 자동 수집 허용 등록을 요구하지 않으며 자동 크롤링 허가를 부여하지도 않는다. 유효 행은 기존 `listings.save`로 병합·중복 제거하고 기존 `summary`로 통계 파일을 갱신한다. 검증 메타데이터는 `data/manual_reviews.csv`에 남긴다. 부적합 행은 제외 사유를 출력하고, 유효 행이 0건이면 운영 DB를 덮어쓰지 않는다.

## 진단 및 온비드 설정

```bash
python crawler.py diagnose --item 제빙기 --manufacturer 카이저 --model IMK-3051 --spec 50kg
python crawler.py diagnose --file /path/input.csv --item 제빙기
python crawler.py onbid --report /path/onbid-report.json
```

진단은 API에 요청하지 않는다. 파일 없음/읽기 오류/스키마 오류/빈 DB, 정제 전후 건수, 행별 최초 제외 이유, 중복 URL, 샘플·180일 초과 제외, 품목·제조사·모델·상태·사양·가격 성격 단계별 남은 표본을 확인할 수 있다. `onbid_key_configured`는 **이 실행 환경**의 키 존재 여부만 표시하며 값은 출력하지 않는다.

예시 코드: `invalid_price` 가격 파싱 불가, `price_out_of_range` 가격 상한/하한, `bundle_quantity` 개별 1개가 아님, `bundle_title` 묶음 제목, `item_keyword_mismatch` 제목 품목 미확인, `irrelevant_title` 부품/무관 물품, `sale_status_basis_mismatch` 게시가·판매상태 불일치, `duplicate_url` 동일 매물, `sample_record` 샘플, `older_than_180_days` 오래된 수집일.

현재 카이저 조회는 정제 7 → 최근 실데이터 7 → 제빙기 4 → 카이저 3 → 모델/50kg 3 → asking 3으로 견적 가능하다. 제조사를 다른 값으로 바꾸면 제조사 단계에서 0이 되는 것을 확인할 수 있다. API 키 누락과 DB 표본 부족은 각각 독립 필드로 출력된다.

온비드 명령은 `MISSING_API_KEY`, `API_REQUEST_FAILED`, `API_RETURNED_ZERO_RECORDS`, `FILTERED_ALL_RECORDS`, `OK`를 구분한다. 키가 있는 경우 키워드별 원시 API 건수·유효 건수·필터별 제외 건수를 보고한다. 실패 원문에 키가 포함될 수 있어 예외 종류/안전한 응답 코드만 기록한다. JSON 오류 응답을 정상 빈 목록으로 해석하지 않도록 보완했고 매각(`dspsMthodCd=0001`)으로 한정했다. 키워드당 기존 100건 첫 페이지 방식은 유지하며 한도에 도달하면 `first_page_limit_reached=true`로 불완전 수집 가능성을 알린다.

추가 설정은 **선택적 `DATA_GO_KR_KEY` 하나**다. 공공데이터포털에서 15157252 활용신청 후 일반 인증키(Decoding)를 로컬 `.env` 또는 CLI 환경변수에 설정하고 실행한다. Streamlit fallback용 키는 관리자 Secrets에 설정한다. 키는 채팅이나 Git에 넣지 않는다. `.env.example`에는 빈 항목만 추가했다. 이번 7건의 수동 DB 조회에는 키가 필요 없다.

## 검증과 배포

- 전체 테스트 41건 통과. 수동 입력→CSV→기존 가격 조회→통계, 검증 정보 누락 차단, 필터 사유, 중복/샘플/오래된 데이터, API 키 없음/오류 응답/낙찰 필터 진단 포함.
- 실제 운영 CSV를 사용하는 로컬 최종 화면에서 카이저 2대의 가격 범위·대표가·표본 수·출처·CSV 다운로드를 PC/모바일로 검증.
- 기존 가상 AI 업로드→수정→최종 목록·다운로드·왕복 이동 브라우저 회귀 테스트 통과. 실제 Gemini 분석과 인증된 온비드 호출은 키 부재로 미검증.
- 문법 검사 및 `git diff --check` 통과. main 커밋/push로 기존 Community Cloud 배포 구조를 유지한다. 관리자 로그와 실제 배포 반영 완료는 확인하지 않았으므로 배포 성공을 단정하지 않는다.
