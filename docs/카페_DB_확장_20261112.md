그러나 모델이 없으면 서로 다른 모델을 묶었고, 모델 미일치 때 사양만 같으면 다른 모델로 대체했다.
실시간 검색은 상세 확인 없이 검색 카드 가격을 사용하고 제조사·사양·상태를 빠뜨렸다.
검증 이력 없이 수집일만으로 운영 데이터가 됐으며, 마지막에는 신품가 감가 추정도 자동 사용했다.

원본은 `data/research/baseline_listings_20261112.csv`, 모델 분포는 `baseline_model_coverage.csv`에 보존했다.
원본 96행의 모든 셀은 운영 CSV 앞 96행과 동일하다. 삭제·값 변경 없이 3행만 덧붙였다.

## C. 검증과 출처 정책

소상공간은 HTTP 200 상세의 JSON-LD Offer 가격/KRW/UsedCondition/재고 상태와 본문을 대조했다.
검색 색인 가격은 저장 근거로 사용하지 않았다. 제조사·모델·가격·상태 미확인은 결측 또는 대기로 기록한다.
판매자 연락처·이미지·본문 전체는 배포하지 않는다. 게시일은 상세에서 확실히 추출되지 않으면 비운다.

출처 조사 결과는 `data/research/source_policy_checks.json`에 있다.
- 소상공간 robots는 공개 제품 경로 허용, 일부 학습 봇 금지. /terms는 404다.
  자동 반복 수집 허가로 해석하지 않고 사용자 요청 범위의 소수 원문 검토만 수행했다.
- 카페다이렉트몰·커피과학 robots/약관은 HTTP 200. 일반 경로와 일부 제한 경로를 구분했다.
  약관의 지적재산권/영리 이용 제한 때문에 자동 수집 승인이라고 단정하지 않았다.
  카페다이렉트몰 3건은 구매와 품절 버튼 모두 숨김이라 현재 상태 불명확 → 대기.
  커피과학은 중고 카테고리까지 확인했으나 검증 가능한 개별 후보 확보를 완료하지 못했다.
- 헬로마켓 robots는 200, 현재 약관 요청은 500. 신규 대량 수집을 하지 않았다.
- 온비드는 실제 키를 사용한 최소 HTTPS 요청 1회가 503 upstream_connection_timeout.
  원문 URL/키를 출력하지 않았고, 정상 0건이나 인증 성공으로 처리하지 않았다.

신규 출처의 자동 수집 등록이나 기관 연락은 하지 않았다. robots 허용은 포괄적 이용 허가가 아니다.

## D. 서비스 연동과 테스트

검증 이력은 별도 CSV에 보관하므로 기존 16열 계약은 유지한다.
`price_quality.eligible`은 검증한 행의 모든 16열 해시·상태·기한을 확인한다.
자동 수집/enrich로 모델·가격·상태가 바뀌면 기존 해시는 무효여서 재검토 전까지 제외된다.
판매 중 게시가 확인 기한은 30일, 공매는 180일로 보수적으로 설정했다.
미검증·정상작동 불명·삭제·검증 만료는 제외한다. 이 기한은 시세 정확도를 보장하는 통계 기준이 아니다.

현재 승인 조건을 충족하는 것은 기존 카이저 2건과 신규 블렌더 3건, 총 5건이다.
운영 원본 99건 중 나머지 94건은 재검증 대기이며 삭제하지 않았다.
관측 파일의 대기 7건 중 새 대기 후보 6건은 운영 원본 99건에 포함되지 않는다.
**같은 가격 성격·사양으로 3건 이상인 검증 그룹이 없어 현재 `price_table.csv`는 헤더만 남는다.**
블렌더 현재 게시가 2건과 카이저 게시가 2건은 `n=2, mid=None`을 반환한다.
종전보다 가격이 덜 나오는 것은 검증되지 않은 기록으로 표본을 채우지 않기 위한 의도적인 변경이다.

수정 내용:
- price_quality.py: 원문 검증 이력·스냅샷·판매 상태·검증 기한 검사, 단일 모델군 선택.
- price.py: 기본 운영 CSV는 검증 통과 행만 사용, 다른 모델의 동일 사양 대체 금지,
  모델 미입력 시 단일 제조사·모델·사양·상태군만 사용, 검증 없이 신품 감가/실시간 공매로 우회 금지.
  검증 이력과 날짜 변경도 캐시 키에 반영.
- crawler.py: 실시간 검색은 후보 발견용. 최대 6개 상세를 3초 이상 간격으로 읽어
  중고·판매중·판매자의 작동 설명을 확인한 행만 후보로 반환.
  제조사·모델이 입력되지 않으면 이 경로로 가격을 억지 생성하지 않는다.
- price.py 실시간 경로: 요청 제조사·모델·사양·상태 모두 확인, 검색 카드만으로 계산 금지.
  모델은 부분 코드가 다른 모델까지 맞지 않도록 경계를 검사. DB와 같은 pandas 분위수 사용.
- listings.py/crawler enrich: 운영 요약도 승인된 스냅샷으로만 재생성.
- onbid_api.py: JSON/XML/HTTP/타임아웃/TLS 구분. 수집 CLI는 첫 오류에서 중단하고 DB에 저장하지 않음.
- cafe_db_report.py/data_diagnostics.py: 검증 데이터 수와 모델별 3건/5건 목표 부족량 보고.

외부 데이터 수집 결과와 격리 합성 테스트는 구분한다.
단위·Streamlit 최종 화면 테스트 및 문법 검사 결과는 작업 최종 보고에 기재한다.
실제 Gemini 사진 분석은 이 환경에 GEMINI_API_KEY가 없어 검증하지 못한다.
앱 사진 탐지/편집 코드와 배포 설정은 변경하지 않았다. 브랜치를 병합해야 운영에 반영된다.

## E. 다음 업데이트

1. 콰이어트원 현재 게시가와 IMK-3051 50kg 각각 비교 가능한 정상 매물 1건 이상을 우선 확보한다.
   권장 5건까지는 각각 3건이 더 필요하다. 판매 완료 게시가를 합쳐 3건으로 만들지 않는다.
2. 우녹스 오븐·CM-110KE 후보는 작동/구성품 확인 후 승격한다. 현재는 미확인 사항을 추정하지 않는다.
3. 냉동고·쇼케이스·정수/온수기·POS·키오스크는 여전히 운영 DB가 비어 있다.
   허용된 API 또는 판매업체의 데이터 제공 협의를 우선하고, 현장/운영자 검토를 보완한다.
4. 공개 상세를 재확인한 검증자는 동일 16열의 fingerprint, checked_at,
   availability(available/sold/deleted/unknown), working_status(seller_reports_normal/tested/unknown),
   status(verified/pending/rejected), 근거 메모를 listing_verifications.csv에 기록한다.
   무조건 verified로 표기하거나 collected_at만 오늘로 변경하면 안 된다.
5. 자동 수집 자체는 원본을 추가할 수 있으나 검증 이력 없는 신규/변경 행은 자동 승격되지 않는다.
   갱신 후 `python cafe_db_report.py`, `python crawler.py diagnose --item 블렌더`로 확인한다.
6. 현재는 원격 판매 완료/삭제를 주기적으로 자동 발견하는 수집기까지 구현하지 않았다.
   재검토 시 상태를 갱신하면 제외되며, 그전에는 최대 검증 유효기간만으로 제한한다.
   정상 작동 여부 역시 판매자 주장 검증 수준이므로 거래 전 실물 확인이 필요하다.
